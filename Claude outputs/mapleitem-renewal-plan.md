> 대상 레포: `D:\웹사이트\maple-item` (Next.js 16 · React 19 · Tailwind v4 · Firebase 12)

## 1. 왜 구조부터 바꾸는가

지금 홈페이지는 히어로 → 특징 3카드 → 3단계 프로세스 → 서버 16개 그리드 → 후기 → CTA → SEO 텍스트, 전형적인 "회사소개형 랜딩" 스택입니다. 문제는 이 사이트에 오는 사람은 브랜드를 알아보러 온 게 아니라 이미 손에 아이템을 들고 "이거 얼마 받을 수 있지"를 알고 싶어서 온다는 점이에요. 특징 카드나 프로세스 설명은 그 질문에 바로 답을 안 해주고 그냥 지나가는 콘텐츠가 됩니다.

그래서 홈 자체를 **방문자 상황별 시나리오 퍼널**로 재편합니다: 장비 하나만 정리할지, 여러 개 한 번에 정리할지, 아직 얼마인지도 모르는 상태인지에 따라 바로 해당 챕터로 이동하고, 보기만 하는 콘텐츠 대신 실제 행동을 돕는 위젯(문의 양식 복사, 품목별 확인 체크리스트)을 배치합니다.

## 3. 새 정보구조 (홈페이지 = 시나리오 퍼널)

```
헤더 (고정)
 ├─ 로고 + 메뉴(홈/이용가이드/후기게시판/소식정보/문의하기) + CTA "판매하기"
 └─ 서브 앵커 내비 (헤더 바로 아래, 스크롤 시 같이 고정)
      · 한 개 판매  · 통판매  · 품목 확인  · 견적·조건

히어로
 ├─ 헤드라인 + 서브카피
 ├─ CTA "카톡으로 매입 문의" (오픈채팅 링크)
 └─ "시세 업데이트: O월 O일 O시 기준" 최신성 배지

[#selling-options] 챕터 1 — 판매 시나리오 분기
 ├─ 카드 A: 장비 한 개 정리
 ├─ 카드 B: 여러 부위 통판매
 └─ 카드 C: 얼마인지부터 확인
 (각 카드 CTA는 전부 오픈채팅으로 수렴, 카드마다 안내 문구만 다르게)

[#bulk-sale] 챕터 2 — 통판매 안내
 ├─ 좌: 통판매 시 준비할 것 리스트
 └─ 우: "카톡에 붙여넣을 문의 양식" 복사 위젯 (placeholder 텍스트 + 복사 버튼)

[#item-check] 챕터 3 — 품목별 확인사항
 └─ 표: 아이템군(무기·방어구 / 장신구 / 드롭템·메획템 / 기타·메소) × 사진에서 확인할 내용

[#trade-terms] 챕터 4 — 견적·거래 조건
 └─ 3단계 원형 프로세스: 서버·옵션 확인 → 견적·비용 확인 → 조건 확인 후 결정

지원 서버 (압축형)
 └─ 기본 8개만 노출 + "더보기"로 16개 펼침 (그리드 전체를 항상 보여주지 않음)

실이용자 후기 (컴팩트)
 └─ 별점 + 후기 + "거래인증" 배지, 가로 슬라이더 3~4장

FAQ (질문형 즉시 노출, 아코디언 아님)
 └─ 3개만 노출 + "FAQ 더 보기" → 이용가이드/FAQ 페이지로

시세·정리 가이드 (선택, 추후 posts 붙일 자리)
 └─ 가이드 글 링크 카드 4~6개 + "전체 보기"

푸터
 ├─ 소개 짧게 + 빠른 링크 + 오픈채팅 CTA만
 └─ 개인 카카오톡 ID 노출 제거 (오픈채팅 링크로 통일)

전역: 우측 하단 플로팅 pill 버튼 ("카톡으로 매입 문의" 아이콘+텍스트, 원형 아이콘 대신)
```

지원서버 그리드를 압축하고 특징 3카드·3단계 프로세스를 시나리오 분기로 대체한 것, FAQ를 문단 텍스트 대신 질문형으로 앞에 노출한 것이 v1 대비 핵심 변경점입니다. 문구·카드 디자인은 참고한 사이트를 그대로 베끼지 않고 메이플아이템 자체 톤으로 새로 씁니다.

## 4. v0 프롬프트

### 4-1. 홈페이지 전체 (메인)

```
Next.js 16 App Router + TypeScript + Tailwind CSS v4 + React 19 기준으로 메이플스토리 아이템 매입(급처) 사이트의 랜딩페이지를 디자인해줘.

브랜드: "메이플아이템" — 유저가 게임 아이템을 급하게 정리(판매)하려 할 때 카카오톡으로 문의하면 경매장 시세 기준으로 가격을 제시해 매입하는 서비스. 방문자는 이미 팔 아이템을 들고 온 상태라는 걸 전제로, 소개보다 "내 상황에 맞는 다음 행동"을 바로 찾게 해주는 게 목표.

컬러 시스템 (다크 프리미엄):
- 배경: #16161A
- 카드/표면: #1F1F26
- 기본 텍스트: #F4F4F5 / 보조 텍스트: #A1A1AA
- 브랜드 포인트(앰버 골드): #E6A400, hover #C98D00 — 버튼·강조 텍스트·배지에만 절제해서 사용
- 성공/인증 배지: #22C55E
- 구분선: #2A2A31
폰트: 제목 Pretendard(굵게, 자간 좁게), 본문은 시스템 산세리프. 다크 배경이라 명도 대비 충분히 확보.

섹션 구성 (순서대로):

1. 헤더 — 로고, 네비(홈/이용가이드/후기게시판/소식정보/문의하기), 우측 "판매하기" CTA 버튼. 스크롤해도 상단 고정.
2. 서브 앵커 내비 — 헤더 바로 아래 얇은 바, "한 개 판매 / 통판매 / 품목 확인 / 견적·조건" 4개 탭. 클릭 시 해당 섹션으로 스크롤. 헤더와 함께 스크롤 시 고정.
3. 히어로 — 굵은 헤드라인 2줄 + 서브카피 1줄 + CTA 버튼(카톡으로 매입 문의). 하단에 "시세 업데이트: 9월 11일 14:00 기준" 같은 작은 최신성 배지.
4. 판매 시나리오 분기 (id="selling-options") — 3개 카드: "장비 한 개 정리"(바꾼 장비나 남는 아이템 하나를 정리하고 싶을 때), "여러 부위 통판매"(메이플을 접거나 한 번에 정리할 때), "얼마인지부터 확인"(매입 가능 여부와 금액이 궁금할 때). 각 카드에 짧은 설명 + CTA 버튼.
5. 통판매 섹션 (id="bulk-sale") — 좌측: 통판매 시 준비할 것 리스트(판매할 부위/남길 장비 구분, 장비창 전체 사진, 일괄 판매 여부). 우측: "카톡에 붙여넣을 문의 양식" 카드 — 서버/판매할 아이템/한개or통판매/희망조건을 채우는 placeholder 텍스트 박스 + "양식 복사" 버튼.
6. 품목별 확인사항 (id="item-check") — 표: 아이템군(무기·방어구·보조무기 / 장신구 / 드롭템·메소획득템 / 기타·메소) × 사진에서 확인할 내용. 다크 테이블 스타일, 헤더 행 강조.
7. 견적·거래 조건 (id="trade-terms") — 3단계 원형 넘버링 프로세스(서버·옵션 확인 → 견적·비용 확인 → 조건 확인 후 결정), 세로 타임라인으로 연결.
8. 지원 서버 — 기본 8개 태그만 보이고 "더보기" 클릭 시 16개 전체 펼쳐지는 접이식 태그 클라우드.
9. 실이용자 후기 — 별점 + 후기 텍스트 + "거래인증" 배지 카드 3~4개, 가로 슬라이더.
10. FAQ — 아코디언 없이 질문 3개를 답변과 함께 바로 노출, 하단에 "FAQ 더 보기" 링크.
11. 하단 CTA 배너 — "지금 급처템 정리하기", 카카오톡 오픈채팅 링크 버튼 하나만 (개인 ID 노출 금지).
12. 푸터 — 서비스 소개 짧게, 빠른 링크(홈/이용가이드/후기게시판/소식정보/문의하기), 오픈채팅 CTA. 다크 배경(#16161A와 톤 맞춤).
13. 우측 하단 플로팅 — 원형 아이콘 대신 "카톡으로 매입 문의" 텍스트가 함께 보이는 pill 버튼, 은은한 부유 애니메이션.

톤: 대칭적인 3분할 카드 반복 대신 섹션마다 레이아웃 비율을 다르게(좌우 비대칭, 표·리스트·카드 섞기) 가져가서 전형적인 AI 생성 랜딩페이지처럼 안 보이게 해줘. 반응형 필수(모바일 375px부터).
```

### 4-3. 아티클 상세 페이지 템플릿 (보조)


## 5. v0 작업 시 주의할 점

- v0는 UI 코드만 생성합니다. Firestore 연동, `lib/posts.ts` 데이터 레이어, admin 인증 로직은 그대로 두고 **v0가 만든 컴포넌트의 마크업/스타일만 가져와 기존 컴포넌트 파일에 이식**하세요.
- 기존 컴포넌트 구조(`components/hero/`, `components/navigation/`, `components/sections/`, `components/ui/`)를 유지하면 유지보수가 편합니다. 새 구조에서는 섹션이 늘었으니(시나리오 분기, 통판매 위젯, 품목별 표, 서버 접이식) `components/sections/` 아래 파일이 몇 개 더 생길 겁니다.
- `app/globals.css`의 `@theme inline` 색상 변수를 위 다크 팔레트로 먼저 바꿔두면, v0 디자인과 무관하게 기존 컴포넌트 톤도 같이 맞춰집니다.
- "카톡에 붙여넣을 문의 양식" 복사 위젯은 `navigator.clipboard.writeText()` 정도로 간단히 구현 가능한 클라이언트 컴포넌트입니다. 새로 만들 컴포넌트 후보로 `components/ui/copy-template.tsx` 같은 이름을 제안합니다.
- 코드 반영 후 반드시 `npm run build`로 에러 확인 (CLAUDE.md의 admin 인증 race condition·revalidation 패턴은 건드리지 않았는지 확인).
- 카카오톡 개인 ID(`han8246`) 노출은 이번 리뉴얼에서 확실히 제거하고 오픈채팅 링크로 통일하는 걸 권합니다.
